Leia isto primeiro

Extrato OFX de qualquer banco, lido do jeito certo

Cada banco gera OFX do seu jeito: tag sem fechamento, arquivo numa linha só, vírgula decimal, cabeçalho dizendo um encoding e mandando outro, FITID repetido, linha de saldo disfarçada de transação. O PzOfx absorve tudo isso e entrega um modelo limpo, com valores exatos e avisos do que veio fora do padrão.

OFX 1.x SGML e 2.x XML Conta e cartão Valores exatos (string) Dia do banco, sem fuso Perfis por banco Sem libxml / XXE Substitui o Ofx.php

O que é o PzOfx?

Uma biblioteca PHP para ler extratos bancários OFX e entregar transações prontas para conciliação. Não depende de framework; no Laravel ganha config publicável, singleton no container e regra de validação.

Tolerante

Tokenizador próprio: não converte SGML em XML, então & solto, < no MEMO ou tag sem fechamento não derrubam a leitura.

Exato

"-1.234,56" vira "-1234.56" — string decimal, somas sem erro de float.

Configurável por banco

De onde vem a descrição, o que fazer com o sinal, se o FITID é confiável — por BANKID, ORG, FID ou tipo de extrato.

Transparente

Nada é corrigido em silêncio: cada desvio vira um aviso com código estável e mensagem em pt_BR/en.

Instalação

O pacote não está no Packagist. Declare o repositório e instale por versão:

// composer.json da aplicação
"repositories": [
    { "type": "vcs", "url": "https://github.com/PuzlPlace/PzOfx.git" }
]
composer require puzl/pzofx:^1.0

Requisitos: PHP ^8.1 com mbstring. No Laravel 10–13 o Service Provider entra sozinho (auto-discovery). Publique a config só se precisar mudar algo:

php artisan vendor:publish --tag=pzofx-config

Início rápido

use Puzl\PzOfx\PzOfx;

$document  = PzOfx::fromFile($request->file('ofx'));
$statement = $document->statement();   // primeiro extrato

$statement->account->bankCode();   // "341"
$statement->firstDate();              // menor data entre as transações
$statement->total();                  // "6437.10" — movimento líquido exato

foreach ($statement as $transaction) {
    $transaction->postedAt;      // DateTimeImmutable
    $transaction->amount;        // "-1234.56"
    $transaction->description;   // MEMO; se vazio, NAME
    $transaction->uniqueId;      // FITID confiável ou fingerprint
}

Entradas aceitas: fromFile() (caminho, SplFileInfo, UploadedFile), fromString() (conteúdo), fromStream() (recurso aberto) e parse(), que detecta sozinho.

Importação típica

Validar no FormRequest, ler, conferir o banco, gravar dentro de transação:

// FormRequest
'file' => ['required', 'file', 'max:10240', new PzOfxFileRule()],

// Service
$statement = PzOfx::fromFile($dto->file)->bankStatements()[0]
    ?? throw new DefaultException('O arquivo não tem extrato de conta.');

if ($statement->account->bankCode() !== $bankAccount->bank_code) { /* banco errado */ }

foreach ($statement->sortedByDate() as $t) {
    $lines[] = [
        'type'        => $t->direction()->value,   // CREDIT | DEBIT
        'date_at'     => $t->postedAt->format('Y-m-d H:i:s'),
        'value'       => $t->amount,
        'fit_id'      => $t->uniqueId,
        'description' => $t->description,
    ];
}
Período da conciliação

Use [$inicio, $fim] = $statement->period(): sempre em ordem, pela menor e maior data das transações (sem transações, o período declarado). O DTSTART/DTEND declarado nem sempre cobre as transações, e a ordem do arquivo varia por banco.

As classes ficam em Puzl\PzOfx\Data (não confundir com Model do Eloquent nem com as Entities da aplicação: são só os dados lidos do arquivo). Tudo é imutável (propriedades readonly) e serializável com toArray().

Um arquivo pode ter várias contas e cartões: statement() devolve o primeiro; percorra statements para todos. Campos proprietários (<BANCO.CANAL>) ficam em $transaction->raw.

Valores

amount é sempre string decimal canônica: sinal opcional, ponto, no mínimo 2 casas. Nunca float no caminho.

No arquivoamount
-1.234,56"-1234.56"
1,234.56"1234.56"
-50,00 / +3.500,00"-50.00" / "3500.00"
1500 / ,5"1500.00" / "0.50"
50.00- / (50.00)"-50.00"
1.234 (um separador só)"1.234" — a especificação manda ler como decimal

Com ponto e vírgula presentes, o último é o decimal. Com um tipo só, uma ocorrência é decimal e várias são milhar. A direção vem do sinal: >= 0 é crédito, < 0 débito — o TRNTYPE é informativo (muitos bancos mandam OTHER ou erram).

Datas e fuso

Aceita 20240115, 202401151234, 20240115123456.789, [-3:BRT], [-03:EST] (offset certo, nome errado — comum no Brasil), [0:GMT], [+5.30:IST], [-3.5]. Data impossível (00000000, 31/02) é erro.

local (padrão)

Data e hora como no arquivo, no fuso da aplicação. 20240229233000[-3:BRT] continua 29/02 23:30.

convert

Aplica o offset e converte. Em UTC, o mesmo lançamento vira 01/03 02:30 — outro dia no extrato.

Extrato é o "dia do banco": use local salvo motivo forte. Na falta de DTPOSTED (Sicoob), a data vem de DTUSER ou do prefixo AAAAMMDD do FITID, com aviso date_fallback.

Encoding e acentos

O cabeçalho não é confiável — há banco que declara USASCII/1252 e manda UTF-8. A regra:

  1. BOM UTF-8 é removido; UTF-16 (com ou sem BOM) é convertido.
  2. encoding na config, se definido, vence tudo.
  3. Bytes que já são UTF-8 válido ficam como estão.
  4. O resto é lido como Windows-1252 (superconjunto prático do ISO-8859-1: €, travessão, aspas curvas), salvo charset declarado diferente.

Entidades (&amp;, &#39;, &nbsp;) são decodificadas; & solto fica como está. Espaços repetidos em MEMO/NAME são colapsados.

Deduplicação

Cada transação traz dois identificadores:

  • fingerprint — SHA-1 de tipo de extrato + conta + data + valor + descrição normalizada (sem acento, maiúscula) + número do documento + ocorrência. Duas tarifas idênticas no mesmo dia ganham fingerprints diferentes (1ª e 2ª ocorrência) e estáveis entre downloads.
  • uniqueId — o FITID quando ele existe e é único no extrato (e o perfil confia nele); senão o fingerprint.
FITID não é confiável em todo banco

Em produção, Caixa manda a data como FITID (271125) e Unicred manda o tipo (DEB PIX), repetidos em dezenas de transações diferentes; BB reaproveita FITID no mesmo dia. Esses dois primeiros já vêm com perfil de fábrica trust_fit_id => false.

FITID — e portanto uniqueId — só é único por conta: o mesmo X1 em duas contas do arquivo não é duplicidade. Misturando contas na mesma tabela, guarde junto $statement->account->key().

Perfis por banco

O primeiro perfil cujo match bate é aplicado por cima de defaults. Critérios: bank_id (comparado pelo código: 0237 = 237; em cartão, que não tem BANKID, vale o FID do sign-on), org (sem caixa e acento), fid, statement (bank/credit_card). Lista = qualquer um dos valores; vários critérios = todos.

Por que strict é o padrão

Em conciliação, importar o extrato sem uma transação é pior que recusar o arquivo: o saldo não fecha e ninguém sabe por quê. Desligue só com o aviso visível para o usuário.

Erros e exceções

Todas estendem PzOfxException (RuntimeException). Decida pelo código, não pela mensagem:

try {
    $document = PzOfx::fromFile($file);
} catch (PzOfxException $e) {
    $e->error();     // PzOfxErrorEnum::INVALID_AMOUNT
    $e->context();   // ['index' => 3, 'field' => 'TRNAMT', 'value' => 'abc']
    $e->getMessage(); // "A transação 3 tem TRNAMT inválido: "abc"."
}
ExceçãoCódigos
PzOfxFileExceptionfile_not_informed, file_not_found, file_not_readable, file_too_large, file_empty
PzOfxParseExceptionnot_ofx, unsupported_encoding, missing_field, invalid_date, invalid_amount, inverted_period (só com fix_inverted_period => false), no_statement
PzOfxConfigExceptioninvalid_config

Laravel e injeção

  • Config: config('pzofx') mesclada; publique com a tag pzofx-config. timezone => null usa app.timezone.
  • Injeção: injete PzOfxParserInterface (recomendado) ou PzOfxParser — os dois resolvem para o mesmo singleton, com a config da aplicação. PzOfxConfig também é singleton.
  • Estático: PzOfx:: usa o parser do container, então mock ou fake no container vale para os dois estilos.
  • Idioma: locale => null segue app.locale a cada mensagem.
  • Validação: new PzOfxFileRule() — arquivo legível, com extrato e com transações (requireTransactions: false aceita extrato vazio). O documento lido fica em $rule->document().
use Puzl\PzOfx\Contracts\PzOfxParserInterface;

public function __construct(private readonly PzOfxParserInterface $parser) {}

$document = $this->parser->parseFile($dto->file);

// ajuste só desta leitura (devolve outra instância; o singleton não muda)
$document = $this->parser->withConfig(['strict' => false])->parseFile($file);

Testando

Código que usa o PzOfx pode ser testado de cinco jeitos — escolha por teste, não por projeto.

1. Lib real (recomendado para o fluxo de importação)

O parser não usa banco, rede nem disco quando recebe conteúdo: o teste é rápido e cobre o comportamento de verdade.

$file = UploadedFile::fake()->createWithContent('extrato.ofx', file_get_contents(base_path('tests/Fixtures/itau.ofx')));

$this->postJson('/bank-reconciliations/import-ofx', ['file' => $file, 'bank_account_id' => $account->id])
    ->assertOk();

2. Builder — dados controlados sem escrever OFX

PzOfxDocumentBuilder gera o OFX e o passa pelo parser real: o documento sai igual ao de produção (fingerprint, uniqueId, perfis da config). toOfx() devolve o arquivo, para usar como upload.

use Puzl\PzOfx\Testing\PzOfxDocumentBuilder;

$document = PzOfxDocumentBuilder::bank('341', '12345-6')
    ->transaction('-50.00', '2024-01-15', 'TARIFA')
    ->transaction('1500.00', '2024-01-16', name: 'PIX RECEBIDO', fitId: 'F2')
    ->ledgerBalance('1450.00')
    ->build();

$ofx = PzOfxDocumentBuilder::creditCard()->transaction('-59.90')->toOfx();

Também: addBankStatement() / addCreditCardStatement() (vários extratos), institution($org, $fid) (escolha de perfil), currency(); na transação, fitId: '' omite o FITID e type: força o TRNTYPE.

3. Fake — no estilo Http::fake()

use Puzl\PzOfx\PzOfx;

PzOfx::fake([$document]);                     // toda leitura devolve $document
PzOfx::fake([$primeiro, $segundo]);            // em ordem; acabou, repete o último
PzOfx::fake(PzOfxErrorEnum::NOT_OFX);           // lança a exceção certa (Parse/File/Config)
PzOfx::fake();                                 // espião: lê de verdade e só registra

// ... executa o código ...

PzOfx::assertParsed();
PzOfx::assertParsedTimes(1);
PzOfx::assertNothingParsed();
PzOfx::assertParsed(fn ($input, $method, $config) => $method === 'parseFile');

O fake vale para PzOfx::, para quem injeta PzOfxParserInterface ou PzOfxParser, para o PzOfxLegacy e para a PzOfxFileRule.

Chame o fake antes de resolver o serviço

Como em todo fake do Laravel: o serviço resolvido do container depois de PzOfx::fake() recebe o fake; um já resolvido antes continua com o parser real.

4. Mock (Mockery / PHPUnit)

// pelo container — vale para injeção e para PzOfx::
$this->mock(PzOfxParserInterface::class)
    ->shouldReceive('parseFile')->once()->andReturn($document);

// sem container
$parser = $this->createMock(PzOfxParserInterface::class);
$parser->method('parseFile')->willThrowException(PzOfxParseException::because(PzOfxErrorEnum::NOT_OFX));
$service = new ImportOfxService($parser);

Mocke o tipo que o serviço injeta. Mock de PzOfxParser (concreta, não é final) também alcança quem injeta a interface; o contrário não.

5. Documento de retorno

As classes de Data são final e imutáveis — não precisam de mock. Para o mock/fake devolver algo, use o builder ou uma fixture: (new PzOfxParser())->parseString($ofx).

Migrando do Ofx.php

Puzl\PzOfx\Compat\PzOfxLegacy é substituto direto do App\Library\Ofx\Ofx: mesmo construtor, mesmas propriedades (bankTransactions, startAt, endAt, bankCode, account, accountDigit, org), mesmo formato de linha e as mesmas chaves de tradução (exceptions.file_not_informed, validation_financial.bank_reconciliations.ofx_file_transactions_is_empty).

use Puzl\PzOfx\Compat\PzOfxLegacy as Ofx;   // era: use App\Library\Ofx\Ofx;

$ofx = new Ofx($request->file);
$ofx->bankTransactions;   // mesmas chaves: type, date_at, value, fit_id, check_num, ref_number, description
$ofx->document();        // o PzOfxDocument completo, para migrar aos poucos

Onde o leitor antigo lia certo, o resultado é idêntico — há teste contra uma cópia fiel do Ofx.php. Arquivo inválido lança PzOfxException com mensagem que não é chave de tradução, então o service atual continua mostrando invalid_ofx_file.

Segurança e limites

  • Sem libxml: <!DOCTYPE> e entidades externas são descartados, não expandidos — sem XXE nem billion laughs.
  • Tamanho: max_file_size (10 MB ≈ 85 mil transações) checado antes de ler o arquivo e em streams. A leitura usa até ~35× o tamanho do arquivo em memória.
  • Profundidade: aninhamento limitado a 64 níveis; aggregate que se repete fecha o anterior.
  • Memória: folhas não viram objeto; 20 mil transações cabem nos 128 MB padrão do PHP.
  • Texto malformado: <!-- ou <![CDATA[ sem fechamento num MEMO viram texto, não engolem o arquivo; tags soltas absorvidas em MEMO/NAME têm teto (sem custo quadrático).
  • Regra de validação: aceita upload ou conteúdo, nunca caminho — string da requisição não aponta arquivo do servidor.
  • Saída: MEMO/NAME vêm do banco — escape ao exibir em HTML e cuidado com =, +, @ no começo ao exportar para planilha.

FAQ

Por que amount é string?

Float erra soma (0.1 + 0.2). Para gravar em coluna decimal, passe a string direto; para inteiro, amountCents().

O TRNTYPE diz CREDIT mas o valor é negativo. Quem vale?

O sinal. Se um banco inverte de forma sistemática, crie um perfil com amount_sign.

O mesmo arquivo importado duas vezes?

Guarde uniqueId com índice único por conta, ou bloqueie por período como a API faz hoje.

Investimentos (INVSTMTRS)?

Fora do escopo: o arquivo é lido sem erro, mas só extratos de conta e cartão viram PzOfxStatement.

Arquivo .ofc?

OFC é o formato antecessor; não é suportado (not_ofx). Peça ao banco o OFX.
